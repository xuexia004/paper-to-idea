# 完整流程演示：从精读到最小验证实验

**这是虚构示例。** 输入为 [synthetic-papers.md](../evals/fixtures/synthetic-papers.md) 中 P01 的六段摘录。论文、模型、数据与报告数字均为人为设定。下列分析是按本仓库 Skill 完成的作者自演练；没有真实文献检索，没有运行模型，不是独立评测。

## 1. Triage

P01 属于 RAG 的条件检索与计算分配问题。Research Question 是：能否按问题选择上下文深度，在保留答案正确率的同时降低平均输入开销？作者的贡献类型是方法与效率评价，核心改变是基于检索熵的 4/8 段门控（P01-S1、S2）。

建议精读其预算与机制论证。对有限资源的 RAG 研究者，低训练需求使它成为可核查的复现候选；但仅凭摘录，没有代码或数据，不能声称可直接复现。相关性判断是 Inference，限于用户关注 RAG 的前提。

### A. Problem Understanding

输入是问题与检索片段，输出是答案，约束是平均上下文开销。作者认定部分问题可少检索；这在摘录中是动机而非已校准的事实（E01、E02）。表内结果说明预算与正确率存在取舍，但不能定位真正瓶颈是检索深度、内容相关性还是门控选择。

### B. Core Insight

作者预期“检索熵反映问题需求 → 按需求分配片段 → 在较低平均预算保留质量”。相对 Fixed-4/8 的关键差异是选择规则；固定片段长度是控制设置，不是独立创新。因果链的第一步没有校准证据，最后一步只有均值对照（E02～E04）。

### C. Method Analysis

问题 → 检索分数 → 熵与阈值 → 选 4 或 8 段 → ToyLM-A 生成 → 规则匹配评价。材料无公式，因此不重构熵的实现或阈值数值。

显式设置是固定段长与输出上限；隐含前提是熵与额外上下文的收益相关。后者属于 **Inference**，需要逐题增益与门控分配对照。没有消融证明熵是必要设计，随机、简单分数间隔或固定深度都可能是替代。

### D. Experimental Analysis

从 E03 计算：Gate 的上下文均值比 Fixed-8 少 `(2048-1536)/2048 = 25%`，正确率低 1 个百分点。这是虚构表内算术，不是“等质量节约 25%”，也不等于端到端延迟减少 25%。没有不确定性或非劣效设定，不能宣称质量相同。

Gate 相对 Fixed-4 同时增加平均 Token 与改变选择机制，因此 7 个百分点的表内差值不能单独归因门控。Fixed-6 和随机 4/8 能分别对比相同平均深度与不依赖难度的分配（E04）。缺少这些对照支持“机制尚未隔离”这一 **Inference**，不支持“门控无效”。

## 4. 三个候选 Ideas

### I01：同预算门控收益归因

- **Research Question**：相同平均 Token 与深度分布下，熵门控是否优于随机分配？
- **Motivation**：预算变化混杂机制解释（G01，E03、E04）。
- **已有不足 / 创新来源**：相对 P01 新增机制对照；真实相关领域覆盖未知。
- **Key Insight（Inference）**：匹配分配规模后保留的差异才与选择策略相关；仍需排除片段内容混杂。
- **Hypothesis**：固定候选池和相同 4/8 分配数量后，门控比随机分配提高配对正确率；最小有意义效应暂设 3 个百分点，由 pilot 校准。
- **竞争解释**：仅由更多平均上下文或偶然抽样导致提升。
- **MVE**：同一数据切片、同一模型，Fixed-4、Fixed-8、Fixed-6、Gate 和随机匹配门控五组；冻结片段与输出上限，比较配对质量、实际 Token 和成本。
- **反证**：匹配预算后增益接近零且区间排除预设有意义效应，则不支持有实际意义的选择收益；区间太宽仅是不确定。
- **预期贡献**：若成立，可提供门控的机制证据；若不成立，可界定预算归因。
- **失败原因**：数据过小、门控校准泄漏、随机条件没匹配预算、基线实现偏差。
- **待查研究**：conditional retrieval、adaptive depth、budget-matched RAG；待执行检索式 `RAG "adaptive retrieval" "budget matched"`。
- **创新性状态**：尚未验证，没有执行外部检索。

### I02：上下文重复率与门控校准边界

- **Research Question**：保持相关证据和总预算后，重复率能否改变门控分配质量？
- **Motivation**：P01 依赖熵与需求相关的隐含前提，单分布尚无边界证据（G02，E02、E05）。
- **已有不足 / 创新来源**：挑战校准前提，而非只增加数据集；外部覆盖待查。
- **Key Insight（Inference）**：检索分数的形状可能同时反映重复性与需求，不能预先认为它就是问题难度。
- **Hypothesis**：在保留答案证据、位置随机化、Token 固定的干预中，重复率升高使门控收益相对固定分配下降；以收益差的重复率交互为主量。
- **竞争解释**：观察变化全部来自答案位置或截断损失。
- **MVE**：80 题，0/25/50% 三档重复率，Gate 与随机匹配分配对照；冻结相关片段和候选池，保存逐例选择。初期只使用一个模型。
- **反证**：控制位置和截断后，门控收益差不随重复率出现可辨变化，则不支持该边界解释；不显著而区间很宽时继续校准样本量或收束结论。
- **预期贡献**：若成立，得到可测校准边界和失效解释；不预先宣称提出新算法。
- **失败原因**：干预同时改变语义、重复率标签不准、生成器对干预不敏感。
- **待查研究**：context redundancy、retrieval entropy calibration、RAG robustness；待执行检索式 `"retrieval augmented generation" redundancy entropy calibration`。
- **创新性状态**：尚未验证。

### I03：门控评价中的答案与证据支持分离

- **Research Question**：门控的答案正确率收益是否伴随检索证据支持？
- **Motivation**：E06 没有测支持性，因此目前无法回答；不把缺测量写成已观察的缺陷（G03）。
- **已有不足 / 创新来源**：评价有效性与归因，真实支持性评价研究覆盖待查。
- **Key Insight（Inference）**：答案匹配不足以识别证据利用，需相关证据干预与人工核验。
- **Hypothesis**：移除唯一支持片段并替换为等长干扰片段后，一部分原正确答案仍被规则判对，但支持性下降；这只是待测预测。
- **竞争解释**：支持性标注不可靠或数据存在多处有效证据。
- **MVE**：50 题人工确认唯一证据，原文/等长删除替换两条件，与 Fixed-6 和 Gate 比较；答案匹配为辅助，人工支持性为主。
- **反证**：核验后存在其他有效证据，或支持性与正确性一致变化，则原“评价分离”解释不成立或需缩窄。
- **预期贡献**：成立时可界定该任务指标的测量边界；不能直接据此提出通用 benchmark。
- **失败原因**：唯一证据难定义、人工标签成本超限、样本太窄。
- **待查研究**：faithfulness、attribution、evidence ablation；待执行检索式 `RAG "evidence ablation" faithfulness evaluation`。
- **创新性状态**：尚未验证。

## 6. I01 的六周实验计划（全部未执行）

约束暂定为硕士生、一张 24GB GPU、六周；是演示假设，未确认真实设备。虚构 ToyLM/ToyQA 不可下载，不作为实际依赖。

1. **核心假设**：匹配平均上下文、深度分布与候选内容后，门控仍有有意义的正确率收益；竞争解释见 I01。
2. **MVE**：先 20 题 pilot，再用冻结的 80 题开发验证切片跑五组；关键比较 Gate 与匹配随机分配。匹配每次分配为相同数量的 4/8 题，记录实际 Token，不能只假定平均相同。
3. **模型与数据**：优先用户已获授权且本地可运行的 3B～8B 指令模型，记录真实名称与版本；先手工构造可审查的短文问答切片。此处尚未选定具体产品，也未核验其许可证/可得性。切片用于机制 pilot，后续真实公开数据验证前不得外推。
4. **Baselines**：Fixed-4、Fixed-8、Fixed-6、Gate、匹配随机 4/8。前两者是质量/预算端点，Fixed-6 对比平均深度；随机分配隔离选择策略。不得把五者都叫严格同预算，端点本来不同。
5. **Metrics**：主量为相同预算下 Gate 减随机分配的配对正确率差。辅助报告逐例错误、Token、总调用、耗时与适用边界。pilot 后选择配对 bootstrap 区间；没有输出时不填 p 值。3 个百分点是待校准决策值，80 题可能无法精确识别它。
6. **控制变量**：模型/代码版本、检索候选池、片段长度、问题、输出上限、提示与解码设置。阈值只在独立开发集定一次，不在评估切片调参。
7. **Ablations**：门控选择改随机，阈值校准方法保持其余条件一致；若增加一种简单分数间隔门控，计入新调用预算并记录。
8. **Error Analysis**：手工审查门控改善/恶化/无变化的配对问题，区分检索缺证据、生成错误、门控误配与规则评价误判。
9. **混杂因素**：不同片段数带来的位置与内容差异、实际 Token 不匹配、校准集泄漏、缓存/预热和随机性。Oracle 只有在引入并标明信息优势后才可作为上界。
10. **资源与阶段**：20 题 × 5 条件 × 1 次 = 100 次 pilot；80 题 × 5 条件 × 2 次 = 800 次验证，共上限 900 次生成。一次随机解码重复不替代独立问题样本。吞吐与显存先实测：若每次平均 t 秒，则生成时间约 `900 × t` 秒，加检索和分析开销；不填虚构 GPU 小时。第 1 周查新/数据/pilot，第 2 周 MVE，第 3～4 周公平基线与消融，第 5 周保留独立 40 题或另一模型作小规模验证（需另计预算），第 6 周整理。扩展前重新计算总调用并核对预算。
11. **继续/停止与失败替代**：匹配后方向为正但区间很宽，仅能称证据不足；若区间上界低于 pilot 后冻结的有意义效应阈值，停止原性能方向，记录机制边界。预算或数据不可行就缩小到归因诊断，不堆新模块。不进行未经授权的付费调用或大规模训练。
12. **潜在贡献结构**：可核验归因问题 → 同预算实验协议 → 门控与竞争解释对照 → 边界与成本 → 可复现材料。需要真实查新和实验后才能判断是否有论文贡献。
