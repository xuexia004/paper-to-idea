# 论文筛选、精读与跨论文积累

## 共同输入与证据表

保留标题、作者、年份、论文/版本 ID、来源 URL 或本地文件、可读范围。元数据未知就写未知。区分原始论文、修订版、补充材料和二手介绍；不同版本的表号或结论不可混用。引用尽量简短，用自己的话概括并保留定位。

| 证据 ID | 论文/版本 | 定位 | 原始观察 | 来源类别 | 限制 |
| --- | --- | --- | --- | --- | --- |
| P01-E01 | P01 / 明确版本 | §、公式/表/图/附录、页码或摘录行 | 不扩张作者主张 | 作者报告 / 用户日志 / 本次复验 | 可见与缺失部分 |

证据协议见入口。推断还应记录证据 ID、推导前提、反例条件；假设还应记录预测、反证和测试。

## Mode 1：Paper Triage

优先读标题、摘要、引言的问题定义、贡献、关键实验和局限；实际没读到的部分不补写。

输出一页以内通常足够：

1. 研究领域、具体子问题与目标场景；用“在什么条件下，谁的什么能力受什么限制”表达 Research Question。
2. Motivation 的证据：实际失败、理论不足、资源瓶颈或评价失真，区分重要性论证与营销性叙述。
3. 作者核心贡献及创新类型：新问题、方法、机制、理论、数据集或评价；组合类型可以并列。
4. 与用户方向的相关性和资源适配理由。没有用户方向时用明确的暂定条件判断。
5. 决策：精读 / 复现候选 / 背景 / 暂缓，并给证据、主要不确定性及下一步。

“复现候选”要求先确认数据、代码或足够实现细节；没有这些只能说值得核查复现条件。

## Mode 2：Deep Reading

### A. Problem Understanding

把任务、输入、输出、约束和失败代价写清楚。作者认为的瓶颈是什么？已有方法的不足是否在合理控制下测量？区分任务重要与所选瓶颈重要。若瓶颈来自猜测，提出能区分它与替代原因的观察。

### B. Core Insight

用一句机制性因果链解释作者为何预期有效。再写最接近基线做了什么、当前方法改变什么，以及该改变为何可能引起结果。将关键贡献、常规组件和实现便利分开；不把模块名称堆叠当作洞察。

### C. Method Analysis

用输入 → 中间状态 → 输出串起流程。对每个关键模块回答功能、设计动机、依赖前提、失败条件和可替代方案。只解释与理解结论有关的公式，说明符号、目标、约束与可见推导；公式不可读就标出缺口。

必要性不能从“作者用了”推断：需要消融、理论或直接对照。没有证据时将必要性写成待检验判断。

### D. Experimental Analysis

建立“主张—实验—观察—可支持范围—其他解释”的对照。逐项检查：

- 数据与划分是否对应目标场景，是否有泄漏、重叠或过度挑选。
- baseline 是否含最接近方法、简单替代和相同资源预算；模型、上下文、检索、调用次数是否公平。
- ablation 是否隔离核心机制，是否同时改变多个因素。
- 指标是否测到研究目标，均值是否掩盖分组失败，误差条/重复实验是否提供不确定性。
- 关键结果究竟是相关性、受控干预证据还是作者解释；有无更简单的替代解释。

未看到原始实验日志只能说作者报告，不声称复验。没有原始数据时不伪造置信区间或显著性。

### E. Limitations

| 类别 | 写法 | 所需依据 |
| --- | --- | --- |
| 作者承认 | 作者在某处明确限制了适用范围 | 原文定位 |
| 支持的推断 | 哪个实验/前提导致对哪些条件担忧 | 证据 ID + 推理 + 适用条件 |
| 待验证猜想 | 某种失败可能存在 | 反证与验证方法，不声称已经发生 |

收尾指出最重要的证据缺口，以及下一项能最大程度改变研究判断的观察。

## 多论文与增量分析

先为每篇固定 ID，再用矩阵比较 Research Question、假设、方法、模型、数据/划分、评价、计算预算和证据强度。不得把不同数据集或预算上的分数直接排列成方法优劣。

关系边使用：继承、互补、竞争、表面矛盾、条件一致；每条边附证据和成立条件。面对冲突先检查：

1. 任务、数据分布、模型能力、评价口径是否一致。
2. 计算/检索/上下文预算、实现、随机性是否可比。
3. 结论是否仅在各自条件内成立，或属于不同因果问题。
4. 剩余冲突能否用统一设置中的单变量实验区分。

按“在明确条件下已解决 / 部分解决 / 在当前已读集合中开放”列问题，最后一类不代表全球未解。寻找跨路线共同的瓶颈，而非仅列方法差异。

在用户授权的研究工作区复用以下最小状态，不强制额外数据库：

- `literature-map.md`：论文清单、条件比较、关系、问题状态与修订记录。
- 各报告的证据表：稳定 ID 与定位；新增论文使用下一个空闲 ID。
- `idea-candidates.md` / `idea-evaluation.md`：Idea ID、依赖证据、检索状态、保留或淘汰原因。

新增论文时明确：“新增什么证据 → 原判断怎样改变 → 哪个实验仍有价值”。用户未要求持久化时在当前对话维护即可，不声称跨会话自动记忆。
