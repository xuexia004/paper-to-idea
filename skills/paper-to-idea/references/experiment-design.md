# 从 Hypothesis 到最小验证实验

## 先决定哪项结果能改变研究判断

将用户选定的 Idea 和证据固定下来；用户要求规划但未选时，对推荐第一项写“暂定方案”。先做能区分机制的 MVE，再决定完整模型或大规模训练。没有执行权限时只交付计划。

MVE 至少明确：

1. 研究假设、竞争解释、适用条件。
2. 干预与对照，观察单位及样本来源。
3. 一个主指标、必要辅助指标、最小有意义效应和决策规则。
4. 关键控制与混杂因素；资源上限与停止条件。
5. 支持、反驳和结果不确定分别意味着什么。

阈值、样本量和预期成本标为设计假设或估算；通过 pilot 测方差/吞吐后调整并记录。小样本没有显著差异不证明等价；若要证明“同等质量”，预先定义非劣效界限与不确定性分析。

## 基线与公平比较

至少考虑最接近方法、简单替代、移除核心机制的消融；必要时加入 oracle 上界，注明其信息优势。不要为了凑数量加入明显弱的方法。

固定模型版本、检索库/快照、数据划分、上下文与调用/Token 预算；对延迟区分缓存、网络、预热和硬件。若预算分配本身是研究变量，应同时报告总预算和分配机制，不能把额外计算的收益当作机制收益。

若无法复现原论文，标出偏离、原因和影响，不声称达到原结果。开放代码或下载成功不等于复现完成。

## 指标、消融与错误归因

指标必须对应假设。RAG 可以按任务选择答案正确性、证据支持、检索覆盖和成本，不默认用单一 LLM judge 作为事实标准；有 judge 时写校准/人工抽查方案与其偏差。

消融逐项隔离假设中的核心变量，安排能区分替代解释的对照。误差分析给出可复核样例、分类规则和分组统计，避免在测试集上反复调参后仍称其为独立验证。

根据研究问题选择跨样本配对、重复运行、置信区间或随机化检验；说明选择理由。没有数据就规划方法，不生成统计结果。随机种子主要控制随机采样/模型解码，不能替代独立数据或跨任务验证。

## 六周资源受限路线

默认路线是待确认的计划框架，按实际预算收缩：

| 阶段 | 可交付证据 | 继续/停止依据 |
| --- | --- | --- |
| 第 1 周 | 数据可得性、简单基线、pilot 的耗时/显存/成本日志 | 数据不可用或预算无法覆盖 MVE 时缩小问题 |
| 第 2 周 | 单变量 MVE、可检查错误样例 | 核心前提未出现则复核测量；不要盲目堆模块 |
| 第 3～4 周 | 最接近基线、机制消融、重复/不确定性分析 | 固定预算后收益消失可否定原机制，转向边界解释 |
| 第 5 周 | 独立数据切片或另一模型的有限外部验证 | 区分可推广结论与单设置案例 |
| 第 6 周 | 整理证据、负结果、可复现实验与论文贡献判断 | 证据不足就收束为明确负结果或下一轮问题 |

优先缓存检索/生成结果、使用开放的小模型或已获授权 API、固定数据切片、避免从头训练。运行前用实测吞吐推算 `条件数 × 样本数 × 重复数` 的总量；API 估算分开输入输出 Token 和调用量，不凭空填价格。

## 失败退路和贡献结构

每个失败原因匹配替代行动：假设被反驳则记录边界或停止，数据问题则换可验证代理任务并标明外推限制，工程超预算则简化对照或缩小样本。不能以不断调参回避否定结果。

潜在论文结构可为：重要且明确的问题 → 可检验机制 → 强且公平基线 → 排除替代解释 → 边界与成本 → 可复现材料。结构完整仍需真实结果与相关研究定位，不能据此承诺投稿层级。

## 实际执行时保留什么

使用用户研究工作区保存配置、模型/数据/代码版本、划分、种子、环境、命令、退出码、原始输出与指标计算方式；训练任务还要记录实际产出的 checkpoint。区分“计划 / 已运行 / 成功或失败 / 尚未复核”。只跑到安装、下载或启动时不得报告训练/评估已完成。
